# Building the prototype ISO

The current build targets Ubuntu 24.04 LTS amd64 with Casper, XFCE, LightDM, Xorg, NetworkManager, and Mozilla Firefox DEB. It is a live-session prototype, not an installer or release build.

Requirements: Docker Desktop with at least 8 GB RAM, 30 GB free disk, and network access. From the repository root run `./scripts/build-iso.sh`. The host script invokes `scripts/build-iso-container.sh` and writes `output/ifba-os-ubuntu-24.04-amd64.iso`. Docker volume `ifba-os-build-cache` holds the Linux root filesystem because the macOS host filesystem is case-insensitive. On Apple Silicon, the build uses amd64 emulation. Removing that volume discards the cached root filesystem. To build without reusing it and preserve the old cache, set `IFBA_BUILD_CACHE_VOLUME=ifba-os-build-cache-recovery ./scripts/build-iso.sh`.

Each build embeds `/usr/share/ifba-os/build-info.json` and installs `ifba-os-version` to print the version, build ID, commit, and UTC build time from the live system. The build also writes `output/ifba-os-ubuntu-24.04-amd64.iso.manifest.json` with the final ISO SHA-256 and byte size. The ISO hash is kept in this external sidecar because embedding an ISO's own final hash inside that same ISO would change the bytes being hashed. The build fails before SquashFS creation if required wallpaper, themes, XFCE defaults, LightDM, Firefox, IFBA AI, SUAP/AVA launchers, network profile, or build metadata are missing or inconsistent.

The image configures an automatic `ubuntu` live user, a Yaru Dark GTK/Xfwm theme, Yaru icons, Inter font, a GTK3 green accent, Xfwm4's built-in compositor, and one bottom XFCE panel with the Whisker application menu, IFBA mark, Super/Windows-key shortcut, app launchers, window list, network/audio indicators, clock, and session actions. One workspace is configured by default; the user can change that count later in XFCE settings. Firefox is sourced from Mozilla's signed APT repository with a pinned signing-key fingerprint; the `firefox-l10n-pt-br` language pack is included, and NetSurf is removed even from a previously cached root filesystem. SUAP/AVA appear as native desktop links and menu launchers, opening only their public HTTPS domains in the configured browser. The supplied full wallpaper is configured for Xfdesktop and the LightDM background. Panel, window-manager, and session defaults are written to the live account, `/etc/xdg`, and `/etc/skel` for future users. The build explicitly sets systemd's default target to `graphical.target` and links LightDM as the display manager; the current UTM run still needs a boot/display diagnosis before desktop startup can be claimed.

The Electron source under `app/` is a separate design prototype; the ISO does not include or autostart it. Window shadows and opacity use Xfwm4's compositor. Picom is not installed, and the desktop does not claim to provide window animations or background blur.

The educational package catalogue is not installed by this image. The GTK assistant settings/chat window, user-scoped D-Bus service, private SQLite data directory, Secret Service integration, NVIDIA text stream, and source-level consent-based visual guidance are included. The visual/X11 dependencies are `python3-xlib`, `python3-pyatspi`, and `at-spi2-core`. The current output ISO must be rebuilt after these visual changes. The assistant has not made a live authenticated request. The live ISO auto-logs into a shared passwordless `ubuntu` account, so do not configure personal API keys or real student data in this demo; it does not provide per-student account isolation. The image has no installer or disk persistence. The generated IFBA identity is provisional. Do not boot this image on real hardware or present it as an official IFBA release.

The build removes the container's systemd-resolved stub before SquashFS creation so the live guest can configure DNS itself. It does not embed host Wi-Fi credentials; UTM Shared networking uses the host uplink through virtual NAT. Never put credentials, API keys, cookies, student data, or personal files in the build context.
