# Building the prototype ISO

The active development builder targets Ubuntu 26.04 LTS amd64 with Casper, KDE Plasma 6, SDDM, NetworkManager, and Mozilla Firefox DEB. It is a live-session prototype, not an installer or production release. The last XFCE implementation remains in branch `legacy/xfce4`; the former container builder is preserved as `scripts/build-iso-xfce4-legacy-container.sh`.

Requirements: Docker Desktop with at least 8 GB RAM, 30 GB free disk, and network access. From the repository root run `./scripts/build-iso.sh`. The helper container uses Ubuntu 24.04 tooling to debootstrap the Ubuntu 26.04 (`resolute`) target; using the 26.04 host container reproduced a `tar failed` error while extracting `base-files`, whereas the 24.04 host container completed that bootstrap. The target rootfs still uses only official 26.04 package sources. The build writes `output/ifba-os-ubuntu-26.04-amd64.iso`. Docker volume `ifba-os-plasma-build-cache` holds a rootfs separate from the historical Ubuntu 24.04 cache. On Apple Silicon, the build uses amd64 emulation. Removing that volume discards the cached Plasma rootfs. To use a separate cache, set `IFBA_BUILD_CACHE_VOLUME=ifba-os-plasma-build-cache-candidate ./scripts/build-iso.sh`.

Before each ISO build, increment `SYSTEM_VERSION` in `tools/build_metadata.py` and commit the build inputs first. Each build embeds `/usr/share/ifba-os/build-info.json` and installs `ifba-os-version` to print the version, build ID, commit, and UTC build time from the live system. The build also writes `output/ifba-os-ubuntu-26.04-amd64.iso.manifest.json` with the final ISO SHA-256 and byte size. The ISO hash is kept in this external sidecar because embedding an ISO's own final hash inside that same ISO would change the bytes being hashed. After a successful build, record its final hash and actual runtime validation in `ISO-RELEASES.md` in a separate documentation-only commit. The Plasma builder checks wallpaper, IFBA color scheme, SDDM, Plasma packages, Firefox, IFBA AI, SUAP/AVA launchers, DHCP profile, and build metadata before SquashFS creation.

The Plasma builder includes SDDM, Plasma 6 Wayland and X11 sessions, KWin, Dolphin, Konsole, Discover, System Settings, NetworkManager/audio widgets, a project color scheme and a native Plasma global-theme package. Its first-run layout defines one centered floating bottom panel with Kickoff, task switching, the system tray and clock; IFBA AI, Firefox, Dolphin and Konsole are included in task-manager launchers. SDDM starts the live account into the X11 Plasma session for the UTM prototype. The one-time session setup applies the user-supplied wallpaper and layout without resetting later wallpaper preferences. The existing Python/GTK assistant backend/service, Mozilla Firefox DEB and ordinary SUAP/AVA links are preserved. The wallpaper, applet layout, SDDM, network, Firefox and assistant startup still need validation in a freshly generated UTM image.

The Electron source under `app/` is a separate design prototype; the ISO does not include or autostart it. KWin is the compositor and window manager in the new build; no second compositor is installed. Animation modes, window decoration refinements, launcher interactions and background blur have not yet been implemented or validated.

The educational package catalogue is not installed by this image. The GTK assistant settings/chat window, user-scoped D-Bus service, private SQLite data directory, Secret Service integration, NVIDIA text stream, and source-level consent-based visual guidance are included. The visual/X11 dependencies are `python3-xlib`, `python3-pyatspi`, and `at-spi2-core`. The current output ISO must be rebuilt after these visual changes. The assistant has not made a live authenticated request. The live ISO auto-logs into a shared passwordless `ubuntu` account, so do not configure personal API keys or real student data in this demo; it does not provide per-student account isolation. The image has no installer or disk persistence. The generated IFBA identity is provisional. Do not boot this image on real hardware or present it as an official IFBA release.

The build removes the container's systemd-resolved stub before SquashFS creation so the live guest can configure DNS itself. It does not embed host Wi-Fi credentials; UTM Shared networking uses the host uplink through virtual NAT. Never put credentials, API keys, cookies, student data, or personal files in the build context.
